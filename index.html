Enriched with each field's nearest Splunk CIM (Common Information Model) equivalent — potential CIM name, whether that field is actually CIM-supported, which data model(s) it falls under, and which Splunk app/TA maps it out of the box vs. needing a custom FIELDALIAS/EVAL — where a mapping was known; scroll the table right to see it. "—" means no known CIM mapping; a blank cell means this field wasn't covered by the CIM enrichment pass at all.

The type= field of every kernel audit record — verified against
        include/uapi/linux/audit.h in the upstream Linux kernel source. This is the field
        that doubles as this catalogue's Event ID for every audit/* log.

      

    

    

      
      
Return codes from Linux-PAM's _pam_types.h — seen (as a name, not the
        raw number) in the res= field of USER_AUTH, USER_ACCT, and USER_ERR records.

      

    

    

      
      
A curated 27-capability subset (of 41 total) of the CAP_* bits from include/uapi/linux/capability.h —
        each is one bit position in the cap_pe/cap_pp/cap_pi
        hex masks of a CAPSET record (event ID 1322).

      

    

    

      
      
A curated set of the standard Linux errno.h values — seen (negated) in
        the exit= field of a failed SYSCALL record (event ID 1300).

      

    

    

      
      
The 15 SSH_DISCONNECT_* reason codes from RFC 4253 §11.1 — sshd prints
        the raw number in its "Received disconnect from ⋯" syslog line, and this catalogue uses that number as the
        Event ID for the ssh/protocol log.

      

    

    

      
      
Real MESSAGE_ID UUIDs from systemd's own catalog
        (catalog/systemd.catalog.in upstream) — the closest Linux analogue to a numeric
        Windows Event ID for anything that isn't routed through the kernel audit subsystem.

      

    

    

      
      
Technique–event associations for the events in this catalogue. Search by technique ID,
        technique name, or event ID.
