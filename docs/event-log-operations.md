# Linux Event Log Operations Reference

Command-line snippets for querying, exporting, and clearing Linux audit and
journal logs — the analogue of `wevtutil`/`Get-WinEvent` on Windows. Covers
`ausearch`/`aureport` (the audit trail, `/var/log/audit/audit.log`) and
`journalctl` (the systemd journal).

## Querying by event type (audit)

Search the audit trail for a specific record type, e.g. USER_LOGIN (event ID
1112), in the last 30 minutes:

```bash
ausearch -m USER_LOGIN --start recent -i
```

Search for a specific record type within an explicit time range:

```bash
ausearch -m USER_CMD -ts 04/15/2025 00:00:00 -te 04/18/2025 00:00:00 -i
```

Search across every audit record generated by a specific user (by audit
UID, which — unlike the effective UID — survives a `sudo`/`su`):

```bash
ausearch -ua 1000 -i
```

Search for all AVC (SELinux/AppArmor) denials system-wide:

```bash
ausearch -m avc -i
```

## Auditing user account creation (event ID 1114 / ADD_USER)

Watch `/etc/passwd` and report every account-creation event with who made
it, across a fleet, via SSH:

```bash
#!/bin/bash
hosts=$(cat hosts.txt)
for host in $hosts; do
  echo "Scanning $host for account creations"
  ssh "$host" "ausearch -m ADD_USER -i" | \
    awk -F'acct="' '{ if (NF>1) print "'"$host"': " $2 }' | cut -d'"' -f1
done
```

The equivalent one-liner locally, formatted with `aureport` instead of
`ausearch`:

```bash
aureport --user --summary -i
```

## Exporting audit/journal logs

**Audit trail, as interpreted text:**

```bash
ausearch -ts today -i > /tmp/audit-today.txt
```

**Audit trail, raw (for forwarding to a SIEM without ausearch's
interpretation layer):**

```bash
cp /var/log/audit/audit.log /tmp/audit-export.log
```

**Journal, a specific unit, as JSON (one object per line — easy to feed to
`jq` or ship to a log pipeline):**

```bash
journalctl -u sshd.service -o json --since "2025-04-15" --until "2025-04-18" > sshd.jsonl
```

**Journal, whole system, as plain export format (portable, can be re-imported
with `journalctl --file`):**

```bash
journalctl -o export --since "-7d" > journal-export.bin
```

**Journal, filtered by a specific MESSAGE_ID (systemd catalog UUID):**

```bash
journalctl MESSAGE_ID=be02cf6855d2428ba40df7e9d022f03d --since "-1d"
```

## Clearing logs

**Rotate the audit log immediately** (does not delete history — moves the
current file to `audit.log.1` per the `num_logs`/`max_log_file` settings in
`/etc/audit/auditd.conf`):

```bash
service auditd rotate
```

**Vacuum (delete) journal entries older than a given age or above a given
total size** — the closest Linux equivalent to `wevtutil cl`, but note this
is a deliberately loud, logged action in its own right (an admin running
`vacuum` is itself worth auditing):

```bash
journalctl --vacuum-time=2d
journalctl --vacuum-size=500M
```

**Remote, across a fleet, rotating the audit log on every host:**

```bash
#!/bin/bash
hosts=$(cat hosts.txt)
for host in $hosts; do
  echo "$host"
  ssh "$host" "service auditd rotate"
done
```

If a host's audit trail needs to be **disabled** rather than rotated (e.g.
for planned, authorized maintenance), that action is itself logged as event
ID 1305 (CONFIG_CHANGE) — see this catalogue's "auditing disabled" entry —
so a normal disable/re-enable cycle always leaves a paper trail even though
nothing was recorded while it was off.
